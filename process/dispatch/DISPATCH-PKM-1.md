## 1. Ray 的原始需求
逐字原文在 `PROMPT.md`，**先讀**。重點：
- Ray 戴 Vision Pro、坐在沙發上，用 Mac Virtual Display 操作他的 **MacBook Neo**。沙發旁沒有高度合適的桌子放鍵盤，手常常會酸。
- 他想用**手機**當輸入裝置：
  - 用手機平常的鍵盤（包括中文輸入法）打字，文字出現在 Mac 上；
  - 手機上有一個好用的**滑鼠介面**，一隻手機就能順暢操控 Mac。
- 要做的事：
  1. 深入搜尋相關文獻和 GitHub 專案；
  2. 設計並做出一款符合需求的手機鍵盤滑鼠（手機 App 或網頁）。
- 原文有一處寫「macmini」，以 MacBook Neo 為主要目標，設計成任何 Mac 都能用。
- **這次也是比較實驗**：Ray 在 MacBook Neo 的 Claude Desktop 下了一模一樣的指令。最後要比對兩邊的效率、研究深度、決定和成品。

## 2. 成功條件
1. **研究（M2）**：`research/REPORT.md`，繁體中文。內容包括：
   - **學術文獻**：手機當作頭戴裝置（VR、AR、Vision Pro）的輸入；手機觸控板和文字輸入；沙發或躺姿的人體工學和手臂疲勞。至少 8 篇，實際打開過才算，讀不到全文就標「僅摘要」。
     - 已知線索：Phonaze（ISMAR 2026），在 Vision Pro 上用軀幹撐著的手機做確認，降低躺姿的手臂疲勞。來源是 `（課程資料夾）`。**這條要自己核對。**
   - **GitHub 開源專案**：手機遙控 Mac 鍵盤滑鼠、網頁觸控板、跨裝置輸入等。至少 8 個。每個記星數、最後更新、授權、平台、做法，以及我們能借什麼。
   - **現成產品**：例如 Remote Mouse、Unified Remote 這類 App。Apple 內建的方案也要查：Universal Control、Mac Virtual Display 的輸入方式、iPhone 能不能當藍牙鍵盤。每個都寫清楚為什麼滿足或不滿足 Ray 的需求。
   - 結論：**有沒有現成的可以直接用？** 如果有，誠實寫出來，這也是一種答案；然後說明為什麼還要自己做，或為什麼不用做。
2. **設計（M3）**：`design/SPEC.md`，寫清楚以下幾點：
   - 架構：手機端、Mac 端、怎麼連線；
   - 鍵盤：中文輸入法打完的字整段送出，加上 Enter、刪除、方向鍵、Cmd 快捷鍵等特殊鍵；
   - 滑鼠：移動、點擊、右鍵、捲動、拖曳、靈敏度；要能單手、橫拿、躺在沙發上用；
   - 安全：只在區域網路用；要有配對碼或 token；別人不能控制 Ray 的 Mac；
   - 延遲目標，以及失敗時怎麼處理（斷線、權限沒開）。
3. **原型（M4、M5）**：做出可以執行的版本。
   - 手機打中文、英文，Mac 收到正確文字；
   - 滑鼠的移動、點擊、右鍵、捲動都能用。
   - 先選最快能讓 Ray 試用的路線，例如 Mac 端小程式加手機網頁，手機不用裝 App。做法由你決定，寫進 DECISIONS。
4. **自測**：
   - 單元測試；
   - 手機尺寸（390 寬，直拿和橫拿）的介面截圖或短片；
   - 在本機量的延遲；
   - 配對碼錯誤時會被拒絕。
   - Mac 端要把按鍵和滑鼠送進系統，需要「輔助使用」權限，**只能由 Ray 自己去系統設定開**。所以你這邊的端對端測試，以權限允許的範圍為限。做不到的部分寫清楚，並附給 Ray 的開權限步驟。
