# 開發過程記錄規則 v1.1（Orca 這邊和 Claude Desktop 那邊共用）

> 公開版本：為了隱私，電腦名稱、使用者名稱、區網 IP（改成 192.168.x.x）、本機路徑、個人助理系統的 id、他人姓名和 email 已遮蔽，P-22 和他人對話有關的原文改成概述（見 docs/PUBLIC-CHECK.md）；其餘逐字未改。

> v1.1（2026-10-23 11:46）：照 Ray 的要求新增「逐字記下 Ray 的每一則 prompt，並統計總數」（第 1 節第 7 點、USER-PROMPTS.md、第 4-1 節、比較卡）。

目的：同一個指令，「Orca＋個人助理架構」和「Claude Desktop」各自做一次，最後用同一套格式比對：
- 誰比較快、比較省 Ray 的力氣；
- 研究查得多深、有沒有錯；
- 做了哪些決定、為什麼；
- 用了哪些工具；
- 成品能不能用。

## 1. 共同規則
1. **時間一律寫台北時間**，格式 `2026-10-23 14:05`。估計的時間要標「約」。
2. **事後補記要標「補記」**，寫清楚是靠記憶還是看紀錄補的。不要假裝是當下記的。
3. **只記真的發生過的事。** 沒打開過的網址不能算「讀過」；只看摘要的標「僅摘要」。
4. 每個來源、決定、問題都有**編號**（S-01、D-01、I-01），其他檔案引用時用編號。
5. 兩邊做完之前**不看對方的成果**，以免互相影響。
6. Ray 每次介入都要記：給指示、回答問題、授權、手動操作（例如在系統設定開權限、安裝 app）。
7. **Ray 的每一則 prompt 都要逐字完整記下**（包括第一則、後來的追問、回答、授權，以及這份記錄規則本身），編號 P-01、P-02…，最後統計總數。見第 4-1 節。

## 2. 檔案（放在專案的 `process/` 資料夾）

| 檔案 | 內容 |
|---|---|
| `PROMPT.md` | 原始指令逐字貼上、收到時間、執行環境（App、模型、電腦、能用哪些工具） |
| `USER-PROMPTS.md` | Ray 的每一則 prompt：逐字全文、時間、分類，最後統計總數（見第 4-1 節） |
| `TIMELINE.md` | 里程碑時間表（見第 3 節） |
| `RESEARCH-LOG.md` | 每一個查過的來源一列（見第 4 節） |
| `DECISIONS.md` | 每一個重要決定一段（見第 5 節） |
| `TOOL-LOG.md` | 用了哪些工具（見第 6 節） |
| `ISSUES.md` | 出錯、走錯路、重做、卡住的地方 |
| `SUMMARY.md` | 最後的比較卡（見第 7 節），兩邊格式完全相同 |

如果 Claude Desktop 不能直接寫檔案，就在對話裡照同樣的標題維持這些內容，最後一次整理成 Markdown，讓 Ray 存成檔案。

## 3. TIMELINE.md：固定里程碑
每一列寫時間和證據（檔案或連結）。沒做到就寫「未達成」。

| # | 里程碑 |
|---|---|
| M0 | 收到指令 |
| M1 | 開始研究 |
| M2 | 研究完成（有報告） |
| M3 | 設計定案（有規格：架構、介面、安全） |
| M4 | 第一次能動的原型：手機打字，Mac 出現文字 |
| M5 | 滑鼠功能能用：移動、點擊、右鍵、捲動 |
| M6 | Ray 在 Vision Pro＋沙發情境真的用過（Ray 確認） |
| M7 | 交付完成（有使用說明和自測證據） |

## 4. RESEARCH-LOG.md：來源表
每個來源一列：

| 欄位 | 寫什麼 |
|---|---|
| 編號 | S-01、S-02… |
| 類型 | 論文／GitHub／官方文件／App／文章／影片 |
| 標題、作者、年份 | 照原文 |
| 網址或 DOI | 實際打開的那一個 |
| 怎麼找到的 | 搜尋詞，或從哪個來源連過來 |
| 讀了多少 | 全文／僅摘要／README／試跑過／只看標題 |
| 重點 | 一兩句 |
| 用在哪 | 對應的決定編號，或寫「沒用到」和原因 |

GitHub 專案多記：星數、最後更新日期、授權條款、平台（iOS／Android／macOS／網頁）、有沒有真的 clone 或執行。

## 4-1. USER-PROMPTS.md：Ray 的每一則 prompt
- 每一則一段，**逐字貼上全文**，不摘要、不改字。附件或貼上的長文也要貼，太長可以另存檔案並註明檔名。
- 每段的欄位：
  - 編號 P-01…；
  - 時間；
  - 分類：
    - 任務指令（新需求、改需求）；
    - 回答 AI 的問題；
    - 授權或核准；
    - 回報或測試結果（例如「我試了，滑鼠太慢」）；
    - 實驗管理（記錄規則、比較相關，像是貼這份規則）；
  - 這一則之後 AI 做了什麼（一句話）。
- 檔案最後統計：
  - 總則數；
  - 各分類的則數；
  - 不算「實驗管理」的則數。這是兩邊比較的主要數字。
- **Orca 這邊**：Ray 的 prompt 都打進總控聊天室，由總控記；只記和這個專案有關的。總控轉給 writer 的指令另外記在 COORDINATOR-LOG，算「內部指令」，不算 Ray 的 prompt。

## 5. DECISIONS.md：決定紀錄
每個決定一段：

```
## D-01 標題
- 時間：
- 問題：要決定什麼
- 選項：A／B／C（各一句優缺點）
- 選擇：
- 理由：（引用來源編號，例如 S-03、S-07）
- 誰決定的：AI 自己／Ray／照前面的規則
- 之後能不能改：容易／難
```

至少要記這些決定：
- 做手機 App、網頁，還是兩者都做；
- 手機和 Mac 怎麼連線（同 Wi-Fi、藍牙、雲端轉送）；
- Mac 端怎麼把按鍵和滑鼠送進系統；
- 安全：怎麼配對、怎麼避免別人控制你的 Mac；
- 滑鼠介面怎麼設計；
- 中文輸入法怎麼處理（直接送文字，還是送按鍵）；
- 要不要用現成的 App 或開源專案。

## 6. TOOL-LOG.md：工具紀錄
- **每一批工具呼叫記一列**：時間、工具（網路搜尋、開網頁、讀檔、寫檔、終端機、瀏覽器、子代理、MCP 等）、目的、結果（成功／失敗）。
- 同一目的的連續搜尋可以合併成一列，寫「搜尋 ×6」。
- 最後統計每種工具的次數。
- **Orca 這邊另外記**：
  - 開了幾個 agent 或 terminal；
  - 總控派工和審查花了幾次來回、多少時間。

  這部分算進「架構成本」。

## 8. 最後核對（Ray 做，或交給總控）
- 兩邊的 SUMMARY.md 放在一起逐列比較。
- 抽查 RESEARCH-LOG 各 3 筆，打開確認真的存在、內容符合。
- 兩個成品各實際用 10 分鐘：打一段中文、一段英文，做一次拖曳、一次捲動，記下好不好用。
